# Памятка для нейросети: сайт турклуба «Связка»

Сначала прочитай `README.md`: там устройство сайта, таблица страниц, данные и роботы. Здесь только правила работы.

## Кто и что

- Турклуб «Связка» (бывшая «Вестра», старый сайт westra.ru остаётся архивом). Новый сайт: https://svyazkaclub.ru на Тильде (тариф Personal, один домен).
- Владелец пишет по-русски и не программист. Отвечай по-русски, простыми словами, без жаргона. Код и комментарии в коде тоже на русском.
- Владелец не любит повторную ручную работу в Тильде. Поэтому весь код живёт здесь, в Тильде только строки-заглушки. Никогда не предлагай «вставьте этот код в Тильду», если задачу можно решить правкой файла в `p/`.

## Как работать

- **Диалог перед публикацией.** Всё, что попадает в `main`, через минуту видно на живом сайте. Перед тем как отправить в `main` видимое изменение, покажи владельцу скриншоты с компьютера и с телефона и дождись «ок». Исключения: новые файлы `p/*.html`, у которых ещё нет страницы в Тильде (их никто не видит), и правки, которые ничего не меняют на экране (комментарии, документация).
- **Шапка и подвал общие для всех страниц.** Ошибка в `p/header.html` или `p/footer.html` ломает весь сайт. Проверяй на ширине 1440, 1100 и 390 пикселей.
- **Над репозиторием одновременно работают несколько сессий.** Перед каждым коммитом делай `git pull`, коммиты держи маленькими, не переписывай чужие куски без нужды.
- **Скриншоты.** github.io недоступен из контейнера. Для проверки открывай файл из `p/` локально в Playwright внутри обёртки, которая подключает `p/header.html` и `p/footer.html`, и подставляй данные таблицы, если сеть их не пускает.
- **Комментарии.** У каждого файла в начале комментарий: что за страница, адрес, откуда данные. У важных блоков короткий комментарий на русском. Места для ручной правки помечай словом `ПРАВИТЬ`, неизвестные данные пиши в `[квадратных скобках]`. После каждой правки обнови `README.md`, если изменилось устройство.
- **Осторожно с кавычками в комментариях внутри `<script>`.** `scripts/search_index.py` вытаскивает из скриптов строки в кавычках `'…'` и `"…"` с русскими буквами и добавляет их в поиск по сайту. В комментариях JS используй «ёлочки», а не прямые кавычки. HTML-комментарии `<!-- -->` в поиск не попадают.
- **Новая страница:** файл в `p/`, пункт меню в `p/header.html`, строка в `PAGES` в `scripts/search_index.py`, инструкция владельцу, как создать страницу в Тильде со строкой-заглушкой.

## Фирменный стиль

- Белый фон, левая колонка с полным меню (на широких экранах всегда открыта, на узких за кнопкой «Меню»), логотип по центру сверху.
- Цвета: чёрный `#161615`, серый текст `#57554F`, линии `#E6E4DF`, камень `#ECEAE5` (подвал, плашки), акцент `#C8410B` (оранжевый, только для акцентов и ссылок).
- Шрифты: Onest для текста, Unbounded для заголовков и кнопок.
- Главная кнопка называется только **«Хочу в горы»** и ведёт на `/start/`. На телефоне она слева, кнопка «Меню» справа, той же ширины.
- Тон текстов тёплый и простой, на «вы». Пример: плашка cookie «У нас тут перекус: печеньки-cookie…».
- Ссылки на westra.ru помечаются стрелкой ↗ автоматически (скрипт в `p/header.html`), руками не нужно.

## Данные и закон

- Персональные данные по 152-ФЗ хранятся в России. Заявки только через Яндекс Формы, никогда через Google Формы или Google-таблицы. Репозиторий публичный: никаких телефонов, почт и анкет в файлах.
- Google-таблица «Связка: календарь» хранит только публичное: события, походы, настройки. Названия листов и столбца A листа «Настройки» код ищет по точному тексту. Если переименовываешь ключ, код должен понимать и старое название.
- В политике (`p/privacy.html`) и согласии (`p/soglasie.html`) пока стоят заглушки `[оператор]`, `[ИНН/ОГРН]` и т. п. Это известно и не срочно.
- Строки с `[ТЕСТ]` в таблице это примеры, их удалят, когда появятся настоящие данные.

## Технические мелочи

- `sv.js` скачивает `p/ИМЯ.html?v=<номер минуты>`, вставляет и заново запускает скрипты, затем шлёт событие `sv:loaded`. На него подписаны шапка (пересчёт меню) и пометка ссылок westra.ru.
- Страницы читают таблицу через `gviz/tq?tqx=out:csv&sheet=<имя листа>`, всегда с явным именем листа (первый лист сейчас «Настройки»). Пока грузится, показывают серые полоски; запасные списки в коде только через 8 секунд или при ошибке.
- t.me, github.io и API GitHub Pages недоступны из контейнера. Роботов проверяют запуском на GitHub (`workflow_dispatch`) и по вкладке Actions.
- Роботы, которые пишут в `main` (календарь, поиск), перед `git push` делают `git pull --rebase`, чтобы два запуска подряд не конфликтовали.

## Хостинг (с 10 ноября 2026)

- Основной: GitHub vanodotcom/svyazka-site, GitHub Pages `https://vanodotcom.github.io/svyazka-site/`; этот адрес записан в p/*.html. Запасной, всегда такой же: GitLab (https://gitlab.com/vanodotcom/svyazka-site), GitLab Pages `https://vanodotcom.gitlab.io/svyazka-site/` (`.gitlab-ci.yml`, задание `pages`, роботы там же, данные только в public).
- 7–10 ноября 2026 аккаунт GitHub был заблокирован, тогда основным был GitLab.
- Роботы работают в обеих копиях: на GitHub через `.github/workflows/` (коммитят в main), на GitLab в CI.
- sv.js запрашивает страницу параллельно с GitHub Pages и GitLab Pages (`BASES`), берёт первый ответ; если ответил GitLab, меняет в странице github.io на gitlab.io. `MIRROR` (jsDelivr) — если не ответил ни один. Заглушки шапки и подвала в Тильде грузят sv.js с GitHub, при ошибке (onerror) с GitLab.
- Каждую правку пушить в ОБА репозитория: сначала GitHub main, затем GitLab main (истории разные: на GitLab коммит поверх его main с деревом GitHub main, без force).
