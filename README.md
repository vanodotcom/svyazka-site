## Как устроен сайт

Сайт собран из четырёх частей, и каждая отвечает за своё.

1. **Тильда** (tilda.cc) хранит адреса страниц, домен svyazkaclub.ru, заголовки для поисковиков, картинки для соцсетей и счётчик Яндекс Метрики. Самого текста страниц в Тильде почти нет.
2. **Этот репозиторий** хранит код и тексты всех страниц (папка `p/`). Основная копия на GitHub: https://github.com/vanodotcom/svyazka-site, GitHub сам публикует её по адресу `https://vanodotcom.github.io/svyazka-site/` (GitHub Pages). Запасная копия, всегда такая же, на GitLab: https://gitlab.com/vanodotcom/svyazka-site, адрес `https://vanodotcom.gitlab.io/svyazka-site/` (GitLab Pages, настройка в `.gitlab-ci.yml`). Запасная появилась, когда 7–10 ноября 2026 аккаунт GitHub был заблокирован. **Каждую правку отправляют в обе копии.**
3. **Google-таблица «Связка: календарь»** хранит то, что меняется часто: события, походы сезона, статус набора в школы, взнос, руководителей школ.
4. **Яндекс Формы** принимают заявки (запись в школу, анкета руководителя похода). Персональные данные по закону 152-ФЗ должны храниться в России, поэтому заявки идут в Яндекс, а не в Google.

Как страница попадает на экран посетителя:

```
Посетитель открывает svyazkaclub.ru/schools/
        │
        ▼
Тильда отдаёт страницу, в которой есть блок T123 «HTML-код» с одной строкой:
  <div data-sv="schools"></div><script src="https://vanodotcom.github.io/svyazka-site/sv.js"></script>
        │
        ▼
sv.js (из этого репозитория) скачивает p/schools.html сразу с GitHub и с GitLab,
берёт ответ, который пришёл первым, и вставляет его на место div
        │
        ▼
Скрипт внутри p/schools.html дочитывает свежие данные из Google-таблицы
(статус набора, расписание) и подставляет их в текст
```

Отсюда главное правило: **чтобы поменять страницу, правят файл в `p/`, а не Тильду.** Через минуту-две после сохранения файла сайт показывает новую версию сам, ничего перевставлять в Тильду не нужно.

Шапка с левым меню (`p/header.html`) и подвал (`p/footer.html`) подключены в Тильде один раз на весь сайт: «Настройки сайта → Шапка и подвал».

На очень широких экранах (шире 1300 пикселей, например Full HD, 2K, 4K) весь сайт стоит колонкой шириной 1300 пикселей по центру, по бокам белые поля. Страница справа от меню заполняет колонку до правого края, между меню и страницей нет линии (у блоков страниц нет своей максимальной ширины). Ширину задаёт `--sv-max` в `p/header.html` (место помечено ПРАВИТЬ). На экранах уже этой ширины вёрстка прежняя, резиновая.

## Что где лежит

| Папка или файл | Что внутри |

| `p/` | Страницы сайта, по одному файлу на страницу. Здесь правят тексты. |
| `sv.js` | Загрузчик: вставляет файл из `p/` в страницу Тильды. Запрашивает страницу сразу с GitHub Pages (основной) и GitLab Pages (запасной) и берёт ту, что пришла первой, поэтому сайт работает, даже если один хостинг недоступен. Трогать почти никогда не нужно. |
| `img/` | Фото, которые не загружены в Тильду: направления школ, галерея (`img/gallery/`), мерч (`img/merch/`), картинки трёх новостей с главной (`img/news/`, кладёт робот). |
| `img/brand/` | Знак, логотипы, «Я в Связке», архив `svyazka-stil.zip` для страницы «Фирменный стиль». |

| `.gitlab-ci.yml` | Публикация запасной копии на GitLab Pages и те же роботы для неё. |
| `news.json` | Новости для главной из Телеграм-канала. Пишет робот, руками не править. |

| `data/passes.json` | Список перевалов для подсказок на странице каталога. Пишет робот, руками не править. |
| `CLAUDE.md` | Правила проекта для нейросети (и полезно прочитать человеку). |

Строка-заглушка для блока T123 (вместо `home` подставьте имя файла):

```html
<div data-sv="home"></div><script src="https://vanodotcom.github.io/svyazka-site/sv.js"></script>
```

В шапке и подвале («Настройки сайта → Шапка и подвал») строка длиннее: если GitHub не открылся, sv.js берётся с GitLab. Этот же sv.js подгружает и все остальные заглушки на странице, поэтому сайт работает, даже если GitHub недоступен.

```html
<div data-sv="header"></div><script src="https://vanodotcom.github.io/svyazka-site/sv.js" onerror="var s=document.createElement('script');s.src='https://vanodotcom.gitlab.io/svyazka-site/sv.js';document.body.appendChild(s)"></script>
```

Для подвала то же самое, только `data-sv="footer"`.

На восьми важных страницах внутрь `<div data-sv="…">` дополнительно вставлен скрытый текст страницы, чтобы её прочитали поисковики и ИИ-поиск, которые не запускают скрипты. Если на такой странице поменялись цена, адрес или расписание, этот текст в Тильде тоже стоит обновить.

### Как устроен файл страницы

Каждый файл в `p/` состоит из трёх частей, сверху вниз:

1. **Комментарий в самом начале** (`<!-- … -->`): что это за страница, её адрес и откуда она берёт данные.
2. **`<style>`**: оформление. Цвета и шрифты фирменного стиля повторяются во всех файлах: чёрный `#161615`, серый текст `#57554F`, линии `#E6E4DF`, камень `#ECEAE5`, акцент (оранжевый) `#C8410B`; шрифты Onest (текст) и Unbounded (заголовки).
3. **Разметка с текстом**, а под ней **`<script>`**, который подтягивает данные из таблицы.

Места, которые меняют руками, помечены словом **ПРАВИТЬ** (найдите его поиском по файлу). Данные, которых пока нет, стоят в **[квадратных скобках]**: например, `[ФИО]` или `[цена]`.

## Откуда берутся данные

### Google-таблица «Связка: календарь»

Адрес: https://docs.google.com/spreadsheets/d/1VaxvNKg-Qq0lQI24aSWUwkhhvPA80JX0QRKDvnT5jNE

Таблица открыта на чтение по ссылке, иначе сайт её не увидит. Сайт перечитывает её не чаще раза в минуту, поэтому правка видна на сайте почти сразу.

| Лист | Столбцы | Где используется |
|---|---|---|
| **Настройки** | A — название (не переименовывать!), B — значение, C — что меняет, D — когда менять | Статус набора, взнос, сезон, руководители и первая встреча каждой школы. Читают главная, школы, направления, запись, походы, «О клубе». На странице «Пешеходный туризм» телеграм-ник вида «@ник» в строке руководителей сам становится ссылкой. |
| **События** | Дата · Время · Событие · Место · Метка · Тип | Календарь, блок «Ближайшее» на главной, вкладки «Расписание» у школ, подписка на календарь. |
| **Походы** | К.с. · Вид · Район · Сроки · Руководитель · Школа · Набор · Ссылка · Описание | Страница «Походы сезона». |

Как работает столбец **«Метка»** в «Событиях»: вкладка «Расписание» у каждой школы показывает только события со своим словом в метке. Горная школа ищет «горная» и уровень (НУ, БУ, СУ, например «горная БУ и СУ»), остальные ищут «пешеход», «водн», «лыжн», «альп». Если будущих событий с меткой нет, школа показывает «первую встречу» из листа «Настройки».

Строки, в которых есть **[ТЕСТ]**, это примеры. Подписка на календарь их пропускает, а со страниц их надо удалить, когда появятся настоящие данные.

Если таблица не загрузилась (нет интернета, таблицу закрыли), страницы через 8 секунд показывают запасной список, который записан прямо в файле (`EVENTS`, `HIKES`, `NEWS`). Это просто страховка, поддерживать его в актуальном виде не обязательно.

### Новости из Телеграма

Робот раз в час читает публичный канал https://t.me/westra и кладёт 6 свежих постов в `news.json`. Главная показывает три из них. Картинки этих трёх новостей робот раз в сутки (около 5 утра по Москве) скачивает к нам в `img/news/` (имя = номер поста), поэтому главная показывает их, даже если Телеграм не открывается. До этого у свежей новости картинка идёт прямо из Телеграма. Картинки новостей, ушедших с главной, робот удаляет сам.

## Роботы

Роботы работают в обеих копиях, каждая обновляет свои данные сама.

**GitHub (основная копия).** Роботы (GitHub Actions) живут в `.github/workflows/`. Они запускаются сами по расписанию и сохраняют результат в репозиторий, только если что-то изменилось. Посмотреть, как они отработали, можно на вкладке **Actions** репозитория. Там же любого робота можно запустить вручную: выбрать его слева и нажать «Run workflow».

| Робот | Когда | Что делает | Программа |
|---|---|---|---|
| Новости из Телеграма | каждый час, в :17 | `news.json` из канала t.me/westra | `scripts/tg_news.py` |
| Подписка на календарь | каждый час, в :07 | `calendar.ics` из листа «События» | `scripts/calendar_ics.py` |
| Поиск по сайту | после каждой правки в `p/` | `data/search.json` из текстов страниц | `scripts/search_index.py` |
| Список перевалов | раз в сутки, ночью | `data/passes.json` из westra.ru/passes | `scripts/passes_index.py` |
| Выгрузка канала (разово) | только вручную | все посты канала в отдельную ветку `tg-dump`, на сайт не попадает | `scripts/tg_dump.py` |

Картинки новостей робот «Новости из Телеграма» скачивает только в запуске около 5 утра по Москве (02 UTC), в остальные часы у свежей новости картинка из Телеграма.

**GitLab (запасная копия).** Всё делает одно задание `pages` в `.gitlab-ci.yml`: перед каждой публикацией оно обновляет новости, календарь и поиск (перевалы и картинки новостей раз в сутки около 5 утра по Москве) и выкладывает сайт. В репозиторий эти файлы не сохраняются, они обновляются только на опубликованном сайте; картинки новостей между запусками хранятся в кэше GitLab. Каждый час публикацию запускает расписание: проект на GitLab → Build → Pipeline schedules. Как прошёл запуск, видно в Build → Pipelines; там же кнопка New pipeline запускает всё вручную.

## Как сделать типовые вещи

Править файлы можно прямо на github.com: открыть файл, нажать карандаш (Edit), исправить, нажать «Commit changes». Через минуту-две обновить страницу сайта. **Ту же правку нужно сделать и на gitlab.com** (файл → Edit → Commit changes), иначе запасная копия отстанет. Проще попросить нейросеть: она правит и отправляет в обе копии сама.

**Поменять дату занятия, добавить лекцию или выезд.** Лист «События» в таблице: новая строка с датой (ДД.ММ.ГГГГ), временем, названием, местом и меткой школы. Код не трогать. Календарь, главная и вкладка «Расписание» нужной школы обновятся сами, подписка на календарь в течение часа.

**Добавить поход сезона.** Лист «Походы» в таблице, новая строка. В столбце «Набор» пишут «есть места» или «набрана». Код не трогать.

**Открыть или закрыть набор в школу, поменять срок набора.** Лист «Настройки»: «Запись в школу: режим», «Набор открыт до», «Набор откроется». Подсказка, что писать, стоит в столбце C.

**Поменять взнос, сезон, руководителя или первую встречу школы.** Лист «Настройки», нужная строка, столбец B.

**Поправить текст на странице.** Найти файл в таблице страниц выше, открыть, найти текст поиском браузера, исправить только слова между тегами (`<p>текст</p>`), не трогая знаки `<`, `>` и кавычки.

**Поменять ссылку на Телеграм или ВКонтакте.** Ссылки записаны прямо в файлах (примерно в 12 штуках). Нужно найти старую ссылку поиском по репозиторию и заменить везде.

**Заменить фото.** Положить файл в `img/` под тем же именем, что и старый. Или загрузить фото в Тильду и вставить его адрес в файл страницы вместо старого.

**Добавить или переставить принт футболки (мерч).** Фото кладут в `img/merch/` по четыре файла на принт: `gN-obe.jpg` (перед и спина рядом, 1600×968), `gN-pered.jpg` и `gN-spina.jpg` (по одной стороне, 900×1063), `gN-krupno.jpg` (крупно сам принт, ширина 900, он же значок в выборе графики); если принт широкий и в значок не влезает, рядом кладут квадратный `gN-znachok.jpg` и пишут его в поле `thumb`. Потом в `p/merch.html` в список `GRAPHICS` добавляют строку. Порядок строк = порядок на странице, первая строка открыта сразу. Сейчас порядок такой: Кот (главный) → картинки на спине (Ледник, Связка в снегах) → простые (Буквы из верёвки, Вся спина, Я в Связке, Знак, Горы на спине) надписи и знаки.

**Добавить новую страницу.**
1. Создать файл `p/новое-имя.html` по образцу похожей страницы (проще всего скопировать, например, `p/history.html`).
2. В Тильде создать страницу с нужным адресом, добавить блок T123 и вставить в него строку-заглушку с `data-sv="новое-имя"`. Опубликовать.
3. Добавить пункт в меню: в `p/header.html` есть строки `<div class="sv-grp">…</div>`, по одной на раздел.
4. Добавить строчку в список `PAGES` в начале `scripts/search_index.py`, чтобы страницу находил поиск.

Пока страница не создана в Тильде, файл в `p/` никому не виден, так что его можно спокойно готовить заранее.

## Если что-то сломалось

**Правка не видна на сайте.** Подождать две минуты и обновить страницу с очисткой кэша (Cmd+Shift+R на маке, Ctrl+F5 на Windows). Если меняли шапку или подвал в настройках Тильды, в Тильде нужно нажать «Опубликовать все страницы».

**Обе копии сайта.** Каждая правка отправляется и на GitHub, и на GitLab (ветка `main` в обоих). Если обновить только одну копию, часть посетителей будет видеть старую версию: посетитель получает ту копию, что ответила быстрее.

**На странице написано «Не удалось загрузить страницу».** sv.js не смог скачать файл из `p/`. Проверьте, что имя в строке-заглушке Тильды совпадает с именем файла, и что файл лежит в ветке `main`. Иногда хостинг просто публикует новую версию (GitHub: вкладка Actions → «pages build and deployment»; GitLab: Build → Pipelines), тогда помогает подождать минуту.

**Вместо событий или походов серые полоски, а потом примеры.** Страница не смогла прочитать Google-таблицу. Проверьте, что таблица открыта по ссылке на чтение, что листы называются ровно «События», «Походы», «Настройки», и что заголовки столбцов не переставлены.

**Настройка из таблицы не применяется.** Чаще всего изменилось название в столбце A листа «Настройки». Сайт ищет настройку по точному названию (большие и маленькие буквы не важны).

**Новости на главной не обновляются.** На GitHub: вкладка Actions → «Новости из Телеграма»; на GitLab: Build → Pipelines. Если там красный крестик, откройте запуск и посмотрите ошибку. Частая причина: Телеграм поменял вид страницы канала, тогда нужно поправить `scripts/tg_news.py` (с этим справится нейросеть).

**Поиск в меню не находит новую страницу.** Страницу забыли добавить в `PAGES` в `scripts/search_index.py`.

**Откатить неудачную правку.** На github.com откройте файл → History → нужная версия → скопируйте её текст обратно. Или попросите нейросеть сделать revert коммита.

## Правила, которые легко нарушить

- **Персональные данные** (анкеты, телефоны, почта участников) собирать только через Яндекс Формы или другие российские сервисы. Не в Google-таблицу и не в файлы репозитория: репозиторий публичный.
- **Не переименовывать** листы таблицы и названия в столбце A листа «Настройки», не переставлять столбцы в «Событиях» и «Походах».
- **Не править руками** файлы, которые пишут роботы: `news.json`, `img/news/`, `calendar.ics`, `data/search.json`, `data/passes.json`. Их перезапишут.
- **Шапка и подвал общие** для всего сайта. Ошибка в `p/header.html` сразу ломает меню на всех страницах, поэтому правку шапки лучше сначала показать кому-то ещё.
- Главная кнопка везде называется **«Хочу в горы»**.
- Ссылки на старый сайт westra.ru получают оранжевую стрелку ↗ и открываются в новой вкладке автоматически, руками это делать не нужно.

## Безопасность

У сайта нет своего сервера и базы данных, поэтому взломать «сам сайт» почти негде. Уязвимое место одно: **аккаунты**, через которые сайтом управляют. Кто войдёт в любой из них, тот сможет поменять или отключить сайт.

| Аккаунт | Что можно сделать, если его захватят | Что включить |
|---|---|---|
| Регистратор домена (r01) | Увести или не продлить svyazkaclub.ru. Самое опасное: без домена сайта нет. | Двухфакторный вход, автопродление, актуальная почта для связи |
| GitHub `vanodotcom` | Поменять код любой страницы, правка видна на сайте через минуту | Двухфакторный вход, сложный пароль |
| GitLab `vanodotcom` (запасная копия) | То же самое: часть посетителей получает страницы с GitLab | Двухфакторный вход; токены доступа (Settings → Access tokens) только известные и со сроком |
| Тильда | Удалить страницы, сменить домен, отключить Метрику | Двухфакторный вход |
| Google-аккаунт с таблицей «Связка: календарь» | Поменять тексты, события, походы на сайте | Двухфакторный вход; редактировать таблицу могут только свои, остальным «просмотр по ссылке» |
| Яндекс (Формы) | Прочитать анкеты людей (персональные данные) | Двухфакторный вход; доступ к ответам только у ответственных |
| Телеграм-канал t.me/westra | Пост сам попадёт на главную сайта | Короткий список админов, двухфакторный вход в Телеграме |

Что уже сделано в коде:
- В репозитории нет паролей, токенов и ключей. Роботы работают без секретов (токен для отправки правок на GitLab хранится только в настройках среды нейросети, не в репозитории). Если когда-нибудь понадобится ключ, его кладут в Settings → Secrets репозитория, а не в файлы: репозиторий публичный.
- Данные из таблицы и новостей выводятся на страницу безопасно (через функцию `esc`), поэтому вставить через таблицу вредный код нельзя. При правке скриптов это нужно сохранить.
- Если Google, GitHub или Телеграм временно недоступны, страницы показывают запасные данные, а не пустоту.

**Не держать всё на одном человеке.** Если у единственного владельца аккаунтов что-то случится, клуб потеряет сайт. Нужен второй доверенный человек с доступом к домену, GitHub, GitLab, Тильде и таблице (или хотя бы записанные в надёжном месте способы восстановления).

### Проверка раз в полгода

- [ ] Домен: срок продления, автопродление включено, почта для связи актуальна.
- [ ] Во всех аккаунтах из таблицы выше включён двухфакторный вход.
- [ ] GitHub → Settings → Collaborators: доступ только у своих. Settings → Integrations (GitHub Apps): нет незнакомых приложений.
- [ ] Google-таблица → «Настройки доступа»: редактируют только свои.
- [ ] Яндекс Формы: доступ к ответам только у ответственных.
- [ ] Админы Телеграм-канала: только свои.
- [ ] Вкладка Actions на GitHub и Build → Pipelines на GitLab: роботы зелёные, нет запусков, которых вы не ждали.
- [ ] GitLab → Settings → Access tokens: только известные токены, срок не истёк (токен `claude` действует до ноября 2027).
- [ ] Второй человек по-прежнему имеет доступ и знает, где что лежит.

## Перенос сайта в другое место

Если репозиторий переедет (другой владелец на GitHub, другой хостинг), адрес сайта с кодом (основной `https://vanodotcom.github.io/svyazka-site/`, запасной `https://vanodotcom.gitlab.io/svyazka-site/`) нужно заменить везде, где он записан:

- `sv.js` (переменные `BASES`, `MAIN`) и строки-заглушки во всех блоках T123 в Тильде;
- в `p/`: `header.html` (поиск), `home.html` (новости), `calendar.html` (подписка), `passes.html` (перевалы) и страницы с фото из `img/`.

Найти все места проще всего поиском `vanodotcom.github.io` по репозиторию. В Тильде достаточно поменять две строки в «Настройки сайта → Шапка и подвал»: sv.js из шапки сам подгружает заглушки всех страниц.

Если сменится Google-таблица, её номер (`1VaxvNKg…`) записан в 10 файлах из `p/` и в `scripts/calendar_ics.py`. Найти поиском по `1VaxvNKg`.

Если сменится Телеграм-канал, поменять `CHANNEL` в `scripts/tg_news.py`.

Тильду при переезде на другой конструктор заменит любая площадка, которая позволяет вставить на страницу свой HTML-код: файлы в `p/` от Тильды почти не зависят. Исключение составляет `p/header.html`: он учитывает устройство страниц Тильды (`#allrecords`, `.t-rec`, `#t-footer`).
