## Как устроен сайт

Сайт собран из четырёх частей, и каждая отвечает за своё.

1. **Тильда** (tilda.cc) хранит адреса страниц, домен svyazkaclub.ru, заголовки для поисковиков, картинки для соцсетей и счётчик Яндекс Метрики. Самого текста страниц в Тильде почти нет.
2. **Этот репозиторий на GitHub** хранит код и тексты всех страниц (папка `p/`). GitHub сам публикует его по адресу `https://vanodotcom.github.io/svyazka-site/` (это называется GitHub Pages).
3. **Google-таблица «Связка: календарь»** хранит то, что меняется часто: события, походы сезона, статус набора в школы, взнос, руководителей школ.
4. **Яндекс Формы** принимают заявки (запись в школу, анкета руководителя похода). Персональные данные по закону 152-ФЗ должны храниться в России, поэтому заявки идут в Яндекс, а не в Google.

Как страница попадает на экран посетителя:

```
Посетитель открывает svyazkaclub.ru/schools/
        │
        ▼
Тильда отдаёт страницу, в которой есть блок T123 «HTML-код» с одной строкой:
  <div data-sv="schools"></div><script src="https://vanodotcom.github.io/svyazka-site/sv.js"></script>
        │
        ▼
sv.js (из этого репозитория) скачивает p/schools.html и вставляет его на место div
        │
        ▼
Скрипт внутри p/schools.html дочитывает свежие данные из Google-таблицы
(статус набора, расписание) и подставляет их в текст
```

Отсюда главное правило: **чтобы поменять страницу, правят файл в `p/`, а не Тильду.** Через минуту-две после сохранения файла сайт показывает новую версию сам, ничего перевставлять в Тильду не нужно.

Шапка с левым меню (`p/header.html`) и подвал (`p/footer.html`) подключены в Тильде один раз на весь сайт: «Настройки сайта → Шапка и подвал».

## Что где лежит

| Папка или файл | Что внутри |
|---|---|
| `p/` | Страницы сайта, по одному файлу на страницу. Здесь правят тексты. |
| `sv.js` | Загрузчик: вставляет файл из `p/` в страницу Тильды. Трогать почти никогда не нужно. |
| `img/` | Фото, которые не загружены в Тильду: направления школ, галерея (`img/gallery/`), мерч (`img/merch/`). |
| `img/brand/` | Знак, логотипы, «Я в Связке», архив `svyazka-stil.zip` для страницы «Фирменный стиль». |
| `scripts/` | Программы на Python, которые запускают роботы GitHub (см. ниже). Руками их запускать не нужно. |
| `.github/workflows/` | Расписание роботов: что и когда запускать. |
| `news.json` | Новости для главной из Телеграм-канала. Пишет робот, руками не править. |
| `calendar.ics` | Подписка на календарь клуба для телефонов. Пишет робот, руками не править. |
| `data/search.json` | Тексты всех страниц для поиска в меню. Пишет робот, руками не править. |
| `data/passes.json` | Список перевалов для подсказок на странице каталога. Пишет робот, руками не править. |
| `CLAUDE.md` | Правила проекта для нейросети (и полезно прочитать человеку). |

Файлы `numpy-….whl`, `potracer-….whl` и папка `scripts/__pycache__/` попали в репозиторий случайно при подготовке картинок. Сайт ими не пользуется, их можно удалить.

Строка-заглушка для блока T123 (вместо `home` подставьте имя файла):

```html
<div data-sv="home"></div><script src="https://vanodotcom.github.io/svyazka-site/sv.js"></script>
```

На восьми важных страницах внутрь `<div data-sv="…">` дополнительно вставлен скрытый текст страницы, чтобы её прочитали поисковики и ИИ-поиск, которые не запускают скрипты. Если на такой странице поменялись цена, адрес или расписание, этот текст в Тильде тоже стоит обновить.

### Как устроен файл страницы

Каждый файл в `p/` состоит из трёх частей, сверху вниз:

1. **Комментарий в самом начале** (`<!-- … -->`): что это за страница, её адрес и откуда она берёт данные.
2. **`<style>`**: оформление. Цвета и шрифты фирменного стиля повторяются во всех файлах: чёрный `#161615`, серый текст `#57554F`, линии `#E6E4DF`, камень `#ECEAE5`, акцент (оранжевый) `#C8410B`; шрифты Onest (текст) и Unbounded (заголовки).
3. **Разметка с текстом**, а под ней **`<script>`**, который подтягивает данные из таблицы.

Места, которые меняют руками, помечены словом **ПРАВИТЬ** (найдите его поиском по файлу). Данные, которых пока нет, стоят в **[квадратных скобках]**: например, `[ФИО]` или `[цена]`.

## Откуда берутся данные

### Google-таблица «Связка: календарь»

Адрес: https://docs.google.com/spreadsheets/d/1VaxvNKg-Qq0lQI24aSWUwkhhvPA80JX0QRKDvnT5jNE

Таблица открыта на чтение по ссылке, иначе сайт её не увидит. Сайт перечитывает её не чаще раза в минуту, поэтому правка видна на сайте почти сразу.

| Лист | Столбцы | Где используется |
|---|---|---|
| **Настройки** | A — название (не переименовывать!), B — значение, C — что меняет, D — когда менять | Статус набора, взнос, сезон, руководители и первая встреча каждой школы. Читают главная, школы, направления, запись, походы, «О клубе». |
| **События** | Дата · Время · Событие · Место · Метка · Тип | Календарь, блок «Ближайшее» на главной, вкладки «Расписание» у школ, подписка на календарь. |
| **Походы** | К.с. · Вид · Район · Сроки · Руководитель · Школа · Набор · Ссылка · Описание | Страница «Походы сезона». |

Как работает столбец **«Метка»** в «Событиях»: вкладка «Расписание» у каждой школы показывает только события со своим словом в метке. Горная школа ищет «горная» и уровень (НУ, БУ, СУ, например «горная БУ и СУ»), остальные ищут «пешеход», «водн», «лыжн», «альп». Если будущих событий с меткой нет, школа показывает «первую встречу» из листа «Настройки».

Строки, в которых есть **[ТЕСТ]**, это примеры. Подписка на календарь их пропускает, а со страниц их надо удалить, когда появятся настоящие данные.

Если таблица не загрузилась (нет интернета, таблицу закрыли), страницы через 8 секунд показывают запасной список, который записан прямо в файле (`EVENTS`, `HIKES`, `NEWS`). Это просто страховка, поддерживать его в актуальном виде не обязательно.

## Роботы GitHub

Роботы (GitHub Actions) живут в `.github/workflows/`. Они запускаются сами по расписанию и сохраняют результат в репозиторий, только если что-то изменилось. Посмотреть, как они отработали, можно на вкладке **Actions** репозитория. Там же любого робота можно запустить вручную: выбрать его слева и нажать «Run workflow».

| Робот | Когда | Что делает | Программа |
|---|---|---|---|
| Новости из Телеграма | каждый час, в :17 | `news.json` из канала t.me/westra | `scripts/tg_news.py` |
| Подписка на календарь | каждый час, в :07 | `calendar.ics` из листа «События» | `scripts/calendar_ics.py` |
| Поиск по сайту | после каждой правки в `p/` | `data/search.json` из текстов страниц | `scripts/search_index.py` |
| Список перевалов | раз в сутки, ночью | `data/passes.json` из westra.ru/passes | `scripts/passes_index.py` |
| Выгрузка канала (разово) | только вручную | все посты канала в отдельную ветку `tg-dump`, на сайт не попадает | `scripts/tg_dump.py` |

## Как сделать типовые вещи

Править файлы можно прямо на github.com: открыть файл, нажать карандаш (Edit), исправить, нажать «Commit changes». Через минуту-две обновить страницу сайта.

**Поменять дату занятия, добавить лекцию или выезд.** Лист «События» в таблице: новая строка с датой (ДД.ММ.ГГГГ), временем, названием, местом и меткой школы. Код не трогать. Календарь, главная и вкладка «Расписание» нужной школы обновятся сами, подписка на календарь в течение часа.

**Добавить поход сезона.** Лист «Походы» в таблице, новая строка. В столбце «Набор» пишут «есть места» или «набрана». Код не трогать.

**Открыть или закрыть набор в школу, поменять срок набора.** Лист «Настройки»: «Запись в школу: режим», «Набор открыт до», «Набор откроется». Подсказка, что писать, стоит в столбце C.

**Поменять взнос, сезон, руководителя или первую встречу школы.** Лист «Настройки», нужная строка, столбец B.

**Поправить текст на странице.** Найти файл в таблице страниц выше, открыть, найти текст поиском браузера, исправить только слова между тегами (`<p>текст</p>`), не трогая знаки `<`, `>` и кавычки.

**Поменять ссылку на Телеграм или ВКонтакте.** Ссылки записаны прямо в файлах (примерно в 12 штуках). Нужно найти старую ссылку поиском по репозиторию и заменить везде.

**Заменить фото.** Положить файл в `img/` под тем же именем, что и старый. Или загрузить фото в Тильду и вставить его адрес в файл страницы вместо старого.

**Добавить новую страницу.**
1. Создать файл `p/новое-имя.html` по образцу похожей страницы (проще всего скопировать, например, `p/history.html`).
2. В Тильде создать страницу с нужным адресом, добавить блок T123 и вставить в него строку-заглушку с `data-sv="новое-имя"`. Опубликовать.
3. Добавить пункт в меню: в `p/header.html` есть строки `<div class="sv-grp">…</div>`, по одной на раздел.
4. Добавить строчку в список `PAGES` в начале `scripts/search_index.py`, чтобы страницу находил поиск.

Пока страница не создана в Тильде, файл в `p/` никому не виден, так что его можно спокойно готовить заранее.

## Если что-то сломалось

**Правка не видна на сайте.** Подождать две минуты и обновить страницу с очисткой кэша (Cmd+Shift+R на маке, Ctrl+F5 на Windows). Если меняли шапку или подвал в настройках Тильды, в Тильде нужно нажать «Опубликовать все страницы».

**На странице написано «Не удалось загрузить страницу».** sv.js не смог скачать файл из `p/`. Проверьте, что имя в строке-заглушке Тильды совпадает с именем файла, и что файл лежит в ветке `main`. Иногда GitHub Pages просто публикует новую версию, тогда помогает подождать минуту.

**Вместо событий или походов серые полоски, а потом примеры.** Страница не смогла прочитать Google-таблицу. Проверьте, что таблица открыта по ссылке на чтение, что листы называются ровно «События», «Походы», «Настройки», и что заголовки столбцов не переставлены.

**Настройка из таблицы не применяется.** Чаще всего изменилось название в столбце A листа «Настройки». Сайт ищет настройку по точному названию (большие и маленькие буквы не важны).

**Новости на главной не обновляются.** Вкладка Actions → «Новости из Телеграма». Если там красный крестик, откройте запуск и посмотрите ошибку. Частая причина: Телеграм поменял вид страницы канала, тогда нужно поправить `scripts/tg_news.py` (с этим справится нейросеть).

**Поиск в меню не находит новую страницу.** Страницу забыли добавить в `PAGES` в `scripts/search_index.py`.

**Откатить неудачную правку.** На github.com откройте файл → History → нужная версия → скопируйте её текст обратно. Или попросите нейросеть сделать revert коммита.

## Правила, которые легко нарушить

- **Персональные данные** (анкеты, телефоны, почта участников) собирать только через Яндекс Формы или другие российские сервисы. Не в Google-таблицу и не в файлы репозитория: репозиторий публичный.
- **Не переименовывать** листы таблицы и названия в столбце A листа «Настройки», не переставлять столбцы в «Событиях» и «Походах».
- **Не править руками** файлы, которые пишут роботы: `news.json`, `calendar.ics`, `data/search.json`, `data/passes.json`. Их перезапишут.
- **Шапка и подвал общие** для всего сайта. Ошибка в `p/header.html` сразу ломает меню на всех страницах, поэтому правку шапки лучше сначала показать кому-то ещё.
- Главная кнопка везде называется **«Хочу в горы»**.
- Ссылки на старый сайт westra.ru получают оранжевую стрелку ↗ и открываются в новой вкладке автоматически, руками это делать не нужно.

## Перенос сайта в другое место

Если репозиторий переедет (другой владелец на GitHub, другой хостинг), адрес `https://vanodotcom.github.io/svyazka-site/` нужно заменить везде, где он записан:

- `sv.js` (переменная `BASE`) и строки-заглушки во всех блоках T123 в Тильде;
- в `p/`: `header.html` (поиск), `home.html` (новости), `calendar.html` (подписка), `passes.html` (перевалы) и страницы с фото из `img/`.

Найти все места проще всего поиском `vanodotcom.github.io` по репозиторию.

Если сменится Google-таблица, её номер (`1VaxvNKg…`) записан в 10 файлах из `p/` и в `scripts/calendar_ics.py`. Найти поиском по `1VaxvNKg`.

Если сменится Телеграм-канал, поменять `CHANNEL` в `scripts/tg_news.py`.

Тильду при переезде на другой конструктор заменит любая площадка, которая позволяет вставить на страницу свой HTML-код: файлы в `p/` от Тильды почти не зависят. Исключение составляет `p/header.html`: он учитывает устройство страниц Тильды (`#allrecords`, `.t-rec`, `#t-footer`).
